# 简历解析引擎规范（Resume Parser Spec）

> 目标：在**纯前端、单文件、可离线**约束下，尽可能把 Word(.docx) / PDF 简历解析为结构化数据，并保证“解析不准也能一键改”。

## 1. 背景

现有工具（`index.html`）已能：
- 浏览器端解压/解析 `.docx`（跳过 `mc:AlternateContent` 的 Fallback、只取段落自身文本）；
- 用 pdf.js 读取 PDF 文本与坐标；
- 关键词识别板块、按日期分组条目、按版面分块兜底、提取头像；
- 渲染成可编辑网页（板块/要点增删拖拽、标签对齐、Markdown 行内标记、导出/打印）。

与成熟开源方案（OpenResume / pyresparser / Docling）相比，仍缺：**行合并、结构化标题判定、字段特征打分、多栏阅读顺序**。本规范给出统一架构与分阶段落地计划。

## 2. 目标与非目标

**目标**
- 统一中间表示（IR）与输出 Schema，解析与渲染解耦。
- 中文、单栏优先；逐步支持多栏与图片型 PDF 的降级。
- 每个字段带置信度；低置信度保留原文，交给编辑器修改。

**非目标**
- 不在主文件内置 OCR（体积过大）；OCR/视觉为可选后端能力。
- 不承诺对任意排版 100% 准确；以“可用 + 可编辑”为准。

## 3. 约束

- 纯前端、单文件、离线可用；零后端依赖。
- 隐私：不上传文件；不把简历内容写入仓库/日志。
- 兼容：现代浏览器；Word 仅 `.docx`；旧 `.doc` 需另存。

## 4. 中间表示（IR）

```json
{
  "text": "示例文本",
  "page": 1,
  "x": 120, "y": 640,
  "size": 12,
  "bold": false,
  "source": "body|table|textbox",
  "order": 12
}
```
图片单独：`{kind:"image", w, h, filter, source:"docx-media|pdf-xobject", order}`

## 5. 解析管线

```
文件 → [1 抽取] → [2 规范化+行合并] → [3 阅读顺序]
    → [4 章节识别] → [5 条目/子段] → [6 字段抽取]
    → [7 置信度/降级] → [8 Resume Model] → 渲染
```

### 5.1 抽取
- **DOCX**：`DecompressionStream` 解压 → `word/document.xml`。
  - 段落只取“自身文本”（排除嵌套 `w:p` 内文本）。
  - 跳过 `mc:Fallback`（避免 Choice/Fallback 双份）。
  - 跳过 `w:del`；表格行优先；文本框按锚点位置插入阅读流。
  - 读 `styles.xml` 获取字号/加粗；图片从 `word/media/*` + rels 映射。
- **PDF**：pdf.js `getTextContent()`，获取 `str + transform`（x/y/size/bold）。
- **图片型 PDF / 扫描件**：文字层不足 → 进入降级（见 §8）。

### 5.2 规范化与行合并
- 归一：全角/半角、NBSP、零宽字符、连续空白、行首项目符号（`·•●▪◦-—–、`）。
- **中文空格归一化（OCR/PDF 常见）**：删除汉字之间、汉字与中文标点之间的空格；修复日期内空格（`2012. 09` → `2012.09`、`2021. 07- 至今` → `2021.07-至今`）。否则标题/关键词会被空格割裂导致板块识别失败。
- **行合并**：若相邻文本片段间距 `< 平均字宽`，拼成同一行（修复 `(123) 456 - 7890` 被拆）。
  - 平均字宽 = Σ(片段宽度) / Σ(字符数)（排除加粗与换行项）。
- 归一后按 `page → 列 → y → x` 排序。

### 5.3 阅读顺序（多栏）
- 对同一页的行按 `x` 做一维聚类（间隙 > 阈值 → 新列）。
- 先列（左→右），列内按 `y`（上→下），再 `x`（左→右）。
- 单栏时退化为按 `y` 排序。

### 5.4 章节识别（中文打分）
中文标题通常不是“全大写+加粗”，改用组合打分（阈值 ≥ 5 判为标题）：

| 特征 | 分值 |
|---|---|
| 命中板块关键词表 | +3 |
| 整行只有一个文本片段（无并列内容） | +2 |
| 字号 ≥ 正文 × 1.15 | +2 |
| 加粗 | +1 |
| 与上一行间距 ≥ 常规行距 × 1.4 | +2 |
| 含数字/年份 | −5 |
| 含冒号 `：:` | −5 |
| 以标点 `，。；` 结尾 | −3 |
| 以项目符号开头 | −3 |

命中阈值后按“最近的标题向上”切分板块；标题前内容归“基本信息”。

### 5.5 条目 / 子段识别
- 板块内，若两行**垂直间距 > 常规行距 × 1.4** → 新子段。
- 或**日期区间行**（`2018.07-2021.06`、`2021.10–至今`、`2012.09-2016.06`）作为子段头。
- 子段内：首行为“时间/单位/职位/项目名”，其余为要点。

### 5.6 字段抽取（特征打分）
每个字段定义特征函数与分值，取分数最高项：

- **姓名**：`2–4 汉字 +3`；加粗 `+2`；含 `@` `−4`；含数字 `−4`；含 `,` `−4`；含 `/` `−4`；命中机构词 `−3`。
- **邮箱**：`/\S+@\S+\.\S+/` `+10`。
- **电话**：`/1[3-9]\d{9}/` 或 `/(\+?\d[\d\s-]{7,})/` `+8`。
- **学校**：含 `大学|学院|学校|中学` `+5`。
- **学历**：含 `本科|硕士|博士|专科|大专` `+5`。
- **日期**：`/(19|20)\d{2}[.\-/年]?\d{0,2}/` `+4`。
- **公司/职位**：含 `公司|集团|有限|科技` `+3`；含 `工程师|经理|主管|负责人` `+3`。

### 5.7 头像
- DOCX：`word/media/*` 取像素面积最大者（排除 < 3000 px² 的图标）。
- PDF：解码内嵌 JPEG（支持 `ASCII85+DCTDecode`），取面积最大；否则保留占位。
- 可选：长宽比 0.6–1.6 过滤、人脸检测优先级。

## 6. 输出 Schema

```json
{
  "name": "示例姓名",
  "title": "求职意向：应聘岗位",
  "photo": "data:image/...",
  "basics": [{"k":"电话","v":"000-0000-0000"}],
  "sections": [
    {"key":"edu","title":"教育背景","icon":"edu","items":[{"time":"20XX.09-20XX.06","school":"某某大学","major":"某某专业"}]},
    {"key":"work","title":"工作经验","icon":"work","items":[{"time":"20XX.XX-至今","company":"某某公司","role":"某某职位","bullets":["…"]}]},
    {"key":"proj","title":"项目经验","icon":"proj","items":[{"name":"某项目","time":"…","desc":"…","tech":"…","bullets":["…"]}]},
    {"key":"skill","title":"专业技能","icon":"skill","items":["…"]},
    {"key":"eval","title":"自我评价","icon":"eval","items":["…"]}
  ],
  "meta": {"confidence":0.82, "warnings":["photo not found"]}
}
```

## 7. 降级策略

1. 文字层充足 → 规则解析（主路径）。
2. 语义板块 < 2 且存在坐标 → **版面分块兜底**（按纵向间距），并按内容自动归类命名。
3. 图片型/扫描件 → 版面兜底；可选懒加载 OCR（不入主文件）或后端 Docling/视觉。
4. 任何低置信度字段 → 保留原文为要点，用户可编辑。

## 8. 评测

- 语料：30–50 份脱敏样本（单栏/双栏、文本框/表格、带/不带照片、扫描件、中英混排）。
- 指标：板块切分准确率、姓名/电话/邮箱命中率、条目结构准确率、头像命中率。
- 回归：每次改动跑语料；禁止把真实简历提交到仓库。

## 9. 参考（仅借鉴思路，不复制代码）

- OpenResume（纯前端 pdf.js + 行合并 + 章节判定 + 特征打分 + 间距子段）。
- pyresparser（spaCy NER + 技能词表，后端）。
- Docling / unstructured（版面分析 + 阅读顺序 + OCR，后端）。
